# マイニュース（個人専用ニュースアプリ）

スマホで毎朝開くだけで、関心ジャンルの見出しを一覧できる静的Webアプリです。
複数のフィード（RSS / Googleアラート / YouTube）を取得し、カテゴリ別に表示します。

- 継続コストゼロ（有料APIは不使用）
- 自動要約なし（見出し＋リンク中心に表示）
- 1つのフィードが落ちても全体は止まらない設計
- カテゴリは折りたたみ可能（初期は開いた状態）。YouTubeはサムネイル付きの動画カードで表示

## しくみ（収集と表示の分離）

| 役割 | ファイル | 種別 |
|---|---|---|
| 収集（Python） | `build_news.py` | フィード取得・整形・フィルタ → `data.js` を出力 |
| 設定 | `feeds.json` | フィード一覧（ここを編集して増減） |
| 表示（ブラウザ） | `index.html` + `app.js` | `data.js`（埋め込みデータ）を読み込んで描画 |

> 収集はビルド時（Python）に行います（ブラウザ直取得は CORS で不可のため）。
> データは `window.NEWS_DATA` として `data.js` に埋め込むので、
> **ローカルサーバ無し・ファイルを直接開くだけ**で表示できます。

## 使い方（ローカル）

1. ライブラリを入れる（初回のみ）
   ```
   pip install -r requirements.txt
   ```
2. データを更新する
   ```
   python build_news.py        # → data.js を作成/更新
   ```
3. **`index.html` をダブルクリックで開くだけ**（ブラウザで表示されます）。
   毎朝は 2→3 を繰り返すか、`build_news.py` を実行後に開いてある画面を再読み込みします。

実行すると各フィードの取得結果が画面に出ます。詳しい記録は `fetch.log` に残ります。

## フィードの増やし方

`feeds.json` を編集します（コードは触りません）。カテゴリごとにフィードを足すだけです。

```json
{
  "categories": [
    { "name": "仕事・AI", "feeds": [
      { "name": "ITmedia AI＋", "url": "https://rss.itmedia.co.jp/rss/2.0/aiplus.xml" }
    ]},
    { "name": "料理", "feeds": [
      { "name": "リュウジのバズレシピ",
        "url": "https://www.youtube.com/feeds/videos.xml?channel_id=UCW01sMEVYQdhcvkrhbxdBpw",
        "type": "video" }
    ]}
  ]
}
```

- 動画フィード（YouTube）は `"type": "video"` を付けるとサムネイル付きで表示。
  YouTubeのURLは `https://www.youtube.com/feeds/videos.xml?channel_id=（チャンネルID）`。
- **秘密のURL（Googleアラート等）は値を書かず** `"url_env": "環境変数名"` で参照します。
  実際の値はローカルは `.env`、GitHub Actions は Secrets に登録（公開ファイルに出さないため）。
- アラート系は `"alert": true` を付けると多層フィルタ（発信元サイト除外・NGワード・必須語）を適用。
  `"require": ["語"]` でタイトルに含むべき語、`"exclude": ["語"]` で個別NG語を指定できます。

## 読めない記事の扱い

本文が読めない記事でがっかりしないよう、2段構えで判定しています。

1. **実ページで確認（確実）**：直リンクの記事は実際にページを見て、
   「有料会員限定」等の文言と、サイトが宣言する `isAccessibleForFree`（無料かどうか）で判定します。
   文言のほうを優先します（無料と申告しつつ本文を隠す媒体があるため）。
   v1.42.0 からは、文言を画面に見える本文の文字だけで探します。メニュー・リンク・ボタン・ふだん隠れている部分の文字は数えません。
   以前はページ全体から探していたので、はてなブログのページに隠れている「引用するにはまずログインしてください」や、
   メニューの「会員限定記事」「雑誌定期購読」に反応して、無料の記事に札を付けていました。
2. **媒体リストで推測（補助）**：Googleニュース経由の記事は実URLに辿り着けないため、
   `paywall.json` の配信元名・**発信元ドメイン**で推測します。1で分かった事実があれば、そちらを優先します。

**⚙設定で「読めない記事」を隠せます。** 隠しても既読にはならず、設定を戻せば出てきます。
以前は「まとめて既読にする」ボタンでしたが、既読にすると埋もれて取り返せないためやめました。

判定結果による表示の違い（読めないものはすべてテーマ内の**末尾**へ回します）：

| 判定 | 意味 | 表示 |
|---|---|---|
| 🔒 有料 | お金を払わないと読めない | 🔒バッジ・見出しを控えめな色に |
| 会員限定 | 登録・ログインすれば無料で読める | 青い「会員限定」バッジ |
| 一部有料 | 無料記事も多いが会員限定も混じる媒体 | 控えめな「一部有料」バッジ |
| 無料 | そのまま読める | バッジなし |

**NHKは受信料契約が要るため、番組も記事も有料扱い**にしています。

媒体リストは `paywall.json` を編集すれば調整できます。
**社名は略称と正式名の両方を書き、ドメインも併記してください。**
部分一致のため、「日経」だけでは「日本経済新聞」に一致しません（実際に取りこぼしていました）。

実ページ確認を止めたい場合は `build_news.py` の `VERIFY_PAYWALL = False` にします
（確認は並行処理で、全体で20〜30秒ほど増えます）。

## 記事を貯める（消えない仕組み）

一度見つけた記事は `archive.json` に貯め、消しません（テーマごと既定500件）。
毎回ゼロから取り直すと、読もうと思っていた記事が翌日には消えてしまうためです。

**貯めた記事は全部 `data.js` に載せます。** 収集側は選びません。
以前は1テーマ30件だけを渡していたため、貯めた記事の73%が画面に届かず、
読み切ると「すべて読み終えました」と出ていました（実際には未読が残っていた）。
**どれを出すかは、既読を知っている表示側が決めます。**

- 画面はテーマごとに30件ずつ描き、下の「**さらに古い記事**」で伸ばします。
- 読んで消えた分は、次の記事が繰り上がります。読むほど古い記事へ降りていけます。
- 取得に失敗したテーマも、蓄積があればそのまま表示します
  （配信側が落ちた日にテーマごと消えるのを防ぐため）。

蓄積の上限はテーマごとに変えられます。上限を超えると**配信日の古い順に捨てます**。
既読かどうかは収集側から分からないため、**未読でも古ければ捨てられます**。
流量の多い技術系テーマだけが上限に達し、人物テーマは到達しないことがほとんどです。

```json
{ "topic": "沢木耕太郎", "keep": 1000 }
```

★お気に入りにした記事は端末に中身ごと保存されるので、蓄積から消えても読めます。

- **`first_seen`**：その記事がアプリに初めて入ってきた日時。NEW判定はこれを使います
  （記事の配信日で判定すると、過去の記事しか無い日は永久にNEWが付きません）。
  **NEW＝「まだ読んでいない、7日以内にアプリへ入ってきた記事」**です。
  何度開いても7日間は光り、読めば消えます。
  ただし**初めて開いた日より前に集まっていた記事には付けません**
  （付けると初回や情報源を増やした日に全件が光り、意味をなさないため）。

**見出しに出る数字は「きょうの新着」（24時間以内に届いた未読）です。**
NEWの印は7日光らせていますが、その数を出すと7日分＝1700件になり、
「今日なにを読めばいいか」の指標として働きません（実測で全件が該当しました）。

| | 意味 | 期間 |
|---|---|---|
| 見出しの数字 | **きょうやること** | 24時間 |
| カードのNEW印 | 数日空けても**見逃さない**ための印 | 7日 |

カテゴリの数字も同じで、大きい数（未読の合計）は小さく添えるだけにしています。

**この数字を押すと「きょうの新着」だけの画面**になります。新着があっても、
どのテーマにあるかスクロールして探すしかなかったためです。
テーマの並びは `feeds.json` の順のまま動かしません（毎日同じ場所にある安心感を保つため）。
別の入口として用意しています。「← 全部を見る」で戻ります。
テーマごとに「✓ 既読に」があり、**今日は見ないテーマを一括で片づけられます**。

**NEWバッジと「1か月以上前の記事」の区切りは、役割が違います。**

| | 意味 | 基準 |
|---|---|---|
| NEW（黄バッジ） | まだ読んでいない**新着** | アプリに入ってきた日 |
| 区切り線 | 記事そのものの**古さ** | 記事の配信日 |
- **情報源を広げる**：蓄積が40件に届かないテーマには、ニュース以外にも当たります。
  Googleニュース検索は `site:` 指定に対応しており、報道以外のページも索引にあるためです。
  既定で `note.com` `hatenablog.com` `1101.com`（ほぼ日）を試します。
- **過去へ遡る補充**：それでも足りなければ、
  `after:2018-01-01 before:2022-01-01` のように**期間を区切って**聞き直し、
  最大20年前まで遡ります。検索は既定だと最近の記事しか返さないためです。

## 情報源を名指しで足す

「ニュースには出ないが、あのサイトには書かれている」を拾うための仕組みです。

```json
{ "topic": "近藤紘一", "sites": ["1101.com", "note.com", "bunshun.jp"] }
```

- 実測：ニュース検索だけでは5件だった近藤紘一が、
  note.com で54件、文藝春秋で20件、はてなブログで10件見つかりました。
- **`sites` のときだけ、見出しに検索語が無くても採用します。**
  求めてしまうと「本文で語っているブログ記事」がすべて落ちるためです。

### 「関連」の印

サイト指定で集めると、**本文で名前に触れているだけ**の記事が混じります
（実測：近藤紘一は66件中51件が見出しに名前なし）。
見出しにテーマの語が無い記事には「**関連**」の印を付け、**テーマ内の末尾へ回します。**
消さないのは、周辺の読み物にも当たりがあるためです。

### 検索語の足し方（同じテーマに複数の切り口）

`group` を同じにすると、別の検索語を1つのテーマに合流できます。

```json
{ "topic": "\"きっとうまくいく\" アーミル", "group": "アーミル・カーン",
  "require": ["きっと、うまくいく", "アーミル"] }
```

**必須語（require）は絞り込みであって、検索の範囲は広げません。**
作品名の記事を拾いたいなら、作品名で検索する行を足す必要があります
（実測：これで「17年ぶり続編へ」等15件が入りました）。

英語のソースには `require_en` を使います。日本語の語を当てると英語の見出しは全滅します。

### そのほかの絞り込み

| 書き方 | 効果 |
|---|---|
| `"min_views": 10000` | 動画の再生回数がこれ未満なら取り込まない |
| `"views_exempt": ["安野貴博"]` | ただし見出しにこの語があれば回数によらず残す |
| `"no_ng": true` | 全体のNGワードを外す（テーマ自体が「Amazon」「セール」等と重なる場合） |
| `"daily_max": 20` | 1日に「新着」として名乗れる数（既定20件） |
| `"minor": true` | **ときどき見れば良いテーマ**（下記） |
| `"fresh_only": 14` | **期限つきの情報**。これより古い記事は蓄積からも消す |
| `"require_also": ["削減", "効果"]` | 必須語に加えて、この語のどれかも見出しに要る（話題でもう一段絞る） |
| `"related_also": ["Claude", "AI"]` | 「関連」（見出しにテーマ名が無い記事）は、この語のどれかが見出しにあるときだけ残す。蓄積済みの分にも当てる（v1.30.0） |
| `"no_backfill": true` | 蓄積が少なくても、過去へ遡る補充（ブログへの深掘り・年ごとの検索）をしない（v1.31.0。会社のニュース用） |
| `"top": true` | 朝刊の**最初の並び**で一番上に出す（ウォッチ銘柄のニュース用。v1.31.0〜v1.36.0 は固定だったが、v1.37.0 から朝刊の［↕ 並べ替え］で動かせる） |

**検索語に `site:` を書いたフィードの必須語は、そのサイトの記事にだけ当てます**（v1.30.0）。
蓄積に必須語を当て直すとき、以前はテーマ内の全フィードの必須語を合わせて使っていたため、
「生成AI」を note・Zenn だけで探しているのに、報道サイトの「○○社が生成AIを導入」まで残り続けていました。
いまは「どれか1つのフィードの条件（必須語と、あればそのサイト）を満たす記事」だけを残します。

**小分類の `check`**：見出しを小分類に振り分ける順です（小さいほど先に判定）。
並べる順（画面の順）は `sections` に書いた順のままなので、「見分ける順」と「見せる順」を別々に決められます。

`fresh_only` は「消さずに貯める」の唯一の例外です。セール情報は開催が終われば
読んでも仕方がないためです（実測：Amazonのセール75件中73件が終了済みでした）。
このテーマは過去へ遡る補充も行いません。

### ときどき見るテーマ

`"minor": true` を書くと、そのテーマは次の扱いになります。

- **「きょうの新着」に数えない**（毎朝の数字を実態に合わせるため）
- カテゴリの**下部**に「ときどき見る」の区切りを挟んでまとめる
- **既定で畳む**（見出しと件数だけ見える。開閉は覚えます）
- **NEWの印は付く**（開いたとき、新しいものが分かる）

**別カテゴリに移す方法は採りませんでした。** 頻度は分類ではなく扱いの強弱なので、
カテゴリを分けると「あの人はどこ？」と探すことになります。同じ場所に控えめに置きます。

実測：アーミル・カーンは1日26件で人物テーマの中で最多でした（沢木耕太郎14件の倍近く）。

**`daily_max` は捨てるための設定ではありません。** 超えた分も蓄積に入り、
掘れば読めます。新着として数えないだけです。
実測で1日142〜175件が入りますが、その6〜7割をClaude Codeと生成AIが占め、
沢木耕太郎の1件がその中に埋もれていました（149件→92件、仕事・AIの占有率 66%→43%）。

### 新着でカテゴリを1行にまとめる（v1.32.0〜）

カテゴリの行に `"fresh_merge": true` を書くと、**朝刊と新着画面で**、そのカテゴリのテーマの新着を1行にまとめます。

```json
{ "name": "人物・作品", "fresh_merge": true, "feeds": [ ... ] }
```

- 件数・「●前回から」・閉じた行の下の見出し・「✓ 片づけ」「✓ ここまで見た」は、まとめた1行で働きます（中の全テーマの新着が片づき、書庫には残ります）。
- 閉じた行の下の見出しは、テーマごとに1本ずつ選び、テーマ名を添えます。開くとテーマ名（チャンネル名）の小見出しで区切ります。
- まとめた行は、中のテーマのうち一番前のものの位置に出ます（動画は記事の後ろ）。
- **件数で自動的にまとめるのではなく、カテゴリで固定**しています。日によって記事の居場所が変わると「昨日あそこにあった」が通用しなくなるためです。
- 書庫のテーマ、テーマの定義、既読・お気に入りの記録は変わりません。
- 今は「人物・作品」と「動画」。1〜2件しかないテーマが1行ずつ並び、開く・片づけるの操作が増えていたためです
  （実測：2026-09-24〜10-07 で、動画は1日2〜4件を1〜3行、人物・作品は1日3〜13件を2〜6行で出していた）。

### 個人ブログの質を見分ける

**機械で測れるのは一部だけです。**

- **はてなブックマーク数**（🔖）を直リンクの記事に付けます（登録もキーも不要の公開API）。
  実測で信号として優秀でした（308件・303件の記事は明らかに良質）。
  **ただし使えるのは直リンクの95件だけ**。残り約9割はGoogleの中継URLで、
  記事の実URLが分からないため引けません。並べ替えには使っていません
  （新しい記事はまだブックマークが付いていないため）。
- 残りは**読み方の記録**で見ます（v1.31.0〜）。「⚙設定 → 発信元ごとの読み方」で、
  発信元ごとに**開いた数**と**開かずに片づけた数（払った・✓片づけ・ここまで見た・👎など）**を並べて見られます。
  開いた数が0で片づけた数の多い発信元は、除外リストに入れる相談ができます。👍の多い発信元は、増やせないか調べられます。
- **👎は「読まずに片づける」印**です。読み方の記録に「👎」と残りますが、**発信元ごとの回数は数えません**。
  以前は数えていましたが、押すと note など媒体まるごとが悪者になるので、ほとんど押されていませんでした。
  これまでに数えた回数は端末に残してあり、書き出しにも入ります（消していません）。

### ブログの種類

| 印 | 中身 |
|---|---|
| 個人ブログ | note・はてなブログ・個人のZenn/Qiita |
| 企業ブログ | ○○ Tech Blog・株式会社○○・公式アカウント |

並び順は変えません（技術テーマでは企業のテックブログも役立つため）。

## 読みたい記事を前に出す

テーマの行に `prefer`（優先）と `demote`（後回し）を書けます。**記事は消えません。**

```json
{ "topic": "井上陽水",
  "prefer": ["出演", "インタビュー", "新曲"],
  "demote": ["BGM", "挿入歌", "カバー"] }
```

`demote` は `prefer` より強く効きます。
「コンサート」のような語は本人の出演でも他人の演奏会でも当たるため、
優先を強くすると『アマチュア音楽家が名曲を披露』のような記事が先頭に来てしまうからです。
完全に消したいものは `exclude` を使います（こちらは表示されなくなります）。
例：アクアワールド大洗は、学校の遠足の記事を `exclude` の「遠足」で外しています（v1.41.0〜。見出しと説明文の両方に当たります）。

**YouTube 以外の動画サイトは後ろへ**（v1.41.0〜）：TVer・ABEMA（動画）・NHKプラス・U-NEXT・Netflix などの記事は、
スマホでは基本見ないので、各テーマの中で有料・会員限定の記事と同じ「いちばん後ろ」の組に回します（消しません）。
同じ話題を1枚にまとめるときも、代表に選ばれにくくします。サイトの住所で見分けます（`build_news.py` の `VIDEO_SITE_HOSTS`）。
文字の記事のサイト（ABEMA TIMES・ニコニコニュース）と、音声の radiko は対象外です。YouTube（「動画」の行）は変わりません。

## ほかの分野から（v1.42.0〜）

自分で選んだテーマの記事だけを読んでいると、ほかの分野の出来事に触れなくなります。
そこで朝刊に「ほかの分野から」の行を置き、テーマの外から1日3本だけ記事を出しています。

記事は、はてなブックマークの分野別の人気記事（無料・登録不要）から選びます。
分野は2つの組を1日ごとに入れ替えます。1つ目の組は世の中・学び・エンタメ、2つ目の組は政治と経済・暮らし・おもしろです。
各分野の1位を1本ずつ選び、順位ははてブ数で付けます。1つの分野から3本選ぶと、2本目と3本目に短い速報が混ざったので、分野ごとの1位にしました。

次のものは選びません。

- 記事の形をしていないページ。ページに記事の印（`og:type`）も公開日も無いもので、道具のページや個人のホームページなどが当たります。
- まとめページ・匿名の日記・動画（`skip_hosts` に書いたサイト）と、有料・会員限定の記事、外国語の記事、プレスリリース。
- もうアプリに入っている記事と、その日に選んだ記事と同じサイトの2本目。

その日の3本は、日本時間の日付が変わって最初の自動更新で選び、その日のうちは選び直しません。人気記事の一覧は1日の中でも入れ替わるからです。
配信が1か月以上前の記事でも、発掘ではなくこの行に出します。古いページがいま多く読まれていることがあるためです。
カードには分野の札（「世の中」など）とはてブ数を付けます。書庫には180本（60日分）まで残します。

文字量・小見出しの数・出典の有無で質を測る方法も試しましたが、数字はサイトの作りで決まり、サイトをまたいだ比べ方には使えませんでした
（2026-10-22 に150ページで確かめました）。まとめページは長く出て、有料の新聞は途中までしか見えないので短く出ます。

設定は `feeds.json` の最後のカテゴリ「ほかの分野から」にあります。やめるときはこのカテゴリを消します。
今の仕組みでは、設定から外したテーマとして書庫の分も消えます。

弱点もあります。はてなブックマークを使う人の好みに寄るので、IT やネットの話題、政治の論争が上がりやすくなります。
毎日新聞のように機械からの取得を断るサイトは中身を確かめられないので、有料かどうか分からないまま出ることがあります。

## 天気とウォッチ銘柄

`feeds.json` の先頭に設定します。どちらも**取れなければ黙って消えます**（ニュースの取得は止めません）。

```json
"weather": { "area": "080000", "point": "水戸" },
"stocks": [ { "code": "2726.T", "name": "パルグループHD" } ]
```

- **天気**：気象庁の公開データ。APIキーも登録も要りません。`area` は地域コード（080000＝茨城県）。
  今日と明日を、アイコン・気温・**通勤（朝6-12時）と退勤（夕12-18時）の降水確率**で出します。
  **時間帯別の天気（晴/曇/雨）は気象庁が公開していません。** 出せるのは1日単位の天気と、
  6時間ごとの降水確率だけです。アイコンは1日単位のものです。
- **ウォッチ銘柄**（`stocks`）：気にしている銘柄の一覧です（**保有とは限りません**）。
  記事とは別のブロック（最下部）に、値段・前日比を並べます。`code` は東証なら「数字.T」、
  日経平均は `^N225`、ドル円は `JPY=X`。上げは赤、下げは青（日本の慣習）。
  あわせて**過去1年の1株配当**（実際に支払われた分の合計）も取ります。配当の記録が無い銘柄は空欄になります
  （無配なのか取れなかったのかは見分けられません）。「今日から1年前まで」で数えるので、配当の権利日が
  前の年より数日ずれた年は、その前後だけ1回分多く・少なく数えることがあります。
  株式分割があった銘柄は、分割後の株数に直した額になります（取得単価も SBI 側で直されるので、利回りはそのまま比べられます）。
  合計の内訳（1回ずつの権利落ち日と額、`divs`）も出します（v1.38.0〜。銘柄を押して開く詳細で見る）。
- **配当の記録の直し**（v1.40.0〜）：Yahoo の配当の記録には誤りがあるので、計算の前に直します。直した回は、内訳に「Yahoo の記録は ○円。直した」と出ます。
  - **分割の日の額**：分割の日の配当が分割前の額のまま記録されることがあります（三井住友FG の 2026/9/29 が 90円、正しくは45円）。
    分割の日とその前1週間の配当を、分割の比で割ったほうが前の回の配当に近ければ直します（29銘柄・分割13回で直ったのはこの1件）。
  - **会社の発表と食い違う額**：権利落ち日の時点の「予想の額」のまま、会社があとで変えても直っていないものがあります
    （2026-10-14 に IR BANK と突き合わせて10件。2020〜2021年に集中。タマホーム 2021年5月期 60円→実際は100円など）。
    `feeds.json` の銘柄の行に `"div_fix": {"権利落ち日": [Yahoo の額, 正しい額]}` と書くと直します。
    **Yahoo の額が今も表と同じときだけ**直します（Yahoo が自分で直したときや、あとの分割で額が変わったときは直さず、更新の記録に「合わない」と出ます）。
  - **点検の道具**：`python tools/check_dividends.py` で、Yahoo の配当を IR BANK と1回ずつ突き合わせます（何も書き換えません。
    月1回の大掃除のときに。食い違いがあれば `div_fix` に足す行の案を出します）。2026-10-14 は、10件を直したあとで一致 523・食い違い 0。
  **取得先は公式に開放されたものではありません。** 使えなくなったら表示が消えるだけです。
- **1年の高値・安値**（v1.33.0〜）：取ってきた1年分の日足の値幅（高値・安値）から出します（`hi`・`lo`、日数は `days`、
  付けた年月は `hi_at`・`lo_at`＝v1.38.0〜）。
  問い合わせの回数は増えません。日足が1年分そろわない銘柄（上場して間もないなど）は、画面に「○か月分」と添えます。
- **10年の配当利回りと1年ごとの配当**（v1.40.0〜）：利回り＝毎月の最後の終値と、その月までの12か月（権利落ちの月で数える）の配当の合計。
  過去10年の最低・最高とその年月（`dy`）、今の月で区切った1年ごとの配当11個（`dyears`、いちばん新しいのが過去1年）、直した配当の回数（`dfix`）。
  10年分の利回りを出すには、その前の1年の配当も要るので、v1.40.0 から**11年分**を取ります（問い合わせの回数は同じ。分割の記録も同じ問い合わせで取る）。
  IR BANK の決算の年ごとの利回りと6銘柄・36件で比べて35件一致（2026-10-14。キヤノン・三菱商事・ポーラ・オルビス・三井住友FG・パルグループ・タマホーム。
  残る1件は三井住友FG の2025年3月期で、IR BANK 側が分割で割った配当を分割前の株価で割っている＝1.61%、こちらは 3.21%）。
- **3年・5年・10年の高値・安値**（v1.36.0〜）：1回の問い合わせで**10年分の日足**（v1.40.0 からは11年分）を取り、そこから1・3・5・10年を切り出します
  （`span` の `"3"`・`"5"`・`"10"` に、高値・安値・それを付けた年月 `hi_at`・`lo_at`・実際に何年分あるか `yrs`）。
  問い合わせの回数は1銘柄1回のままで、更新は29銘柄で約3秒長くなります（2026-10-13 の実測 11.7秒→15.0秒）。
  「○年分」は最新の取引日の○年前の同じ日から数えます（Yahoo の range=1y と同じ数え方なので、1年の数字は v1.35.0 までと同じ）。
  昔の株価は**株式分割のぶんを今の物差しに割り戻した値**です（三井住友FG の 2020年3月の安値 2,507.5円 → 6分の1の 417.92円。
  外部の銘柄ページと3社で突き合わせ済み）。10年分の値動きそのものは公開側に出しません。
  10年分が取れないときは1年分で取り直し、画面の期間の切り替えは出ません。
- **前日比**は、最新の値と「その前の取引日の終値」の差です。v1.30.0 までは約5営業日前の終値と比べていました
  （2026-10-07 の実例：本当の前日比 +49円 が +17円 と出ていた）。
- **天気の下の一行**：保有株を読み込んでいない端末では、ウォッチ銘柄を3つまで並べます（押すと最下部へ）。
  保有株を読み込んだ端末では、代わりに**含み損益と取得利回りの合計**を出します。
- **会社のニュース**：カテゴリ「お金」のテーマ「**ウォッチ銘柄のニュース**」で、1社ずつ Google ニュースを検索します。
  見出しに社名がある記事だけを残し、朝刊では**最初は一番上**に出します（`"top": true`。v1.37.0 から朝刊の［↕ 並べ替え］で動かせます）。
  会社のニュースは古いものを読まないので、30日より前の記事は取りに行かず、過去への補充もしません
  （`"max_age_days": 30`・`"no_backfill": true`）。新着に名乗るのは1日15件まで（試し運転で1日約23件）。
  銘柄を増やしたら、このテーマにも1行足してください。
  同じ名前の別物は、試し運転で実際に混ざったものだけ外しています（オリックスの野球＝検索語でも除外、
  ENEOS のスポーツチーム、ピジョンと同じ名前の人名など）。

### 保有株（この端末だけ・v1.31.0〜）

**株数・取得単価・損益は、どこにも公開しません。** スマホのブラウザの中だけに置き、
公開しているウォッチ銘柄の株価・配当と組み合わせて、画面の中で計算します。

1. SBI証券の「ポートフォリオ一覧」で CSV を保存する（Shift_JIS のままでよい）
2. ⚙設定 →「保有株（この端末だけ）」の **⬆ CSV を読み込む** でそのファイルを選ぶ
3. 銘柄数と、ウォッチ銘柄に無い銘柄が出るので、よければ **この内容に置き換える**

| 出るところ | 中身 |
|---|---|
| 天気の下 | 💼 含み損益の合計（率）・取得利回り（長期保有・優待の札を付けた銘柄があれば、高配当だけ） |
| 最下部のウォッチ銘柄 | 上に合計（取得額→評価額・含み損益・取得利回り）。その下を「💼 持っている」「👀 気になる」に分けて並べる |

ウォッチ銘柄の1銘柄は、次の3行です（v1.33.0〜）。

| 行 | 中身 |
|---|---|
| 1行目 | 名前・役割の札・株価・前日比 |
| 2行目 | 配当（過去1年の1株配当）と利回り（持っていれば「取得 ○% ／ いま ○%」、持っていなければ「いま ○%」）・選んだ期間の安値〜高値の中のいまの位置（棒の上の点） |
| 3行目（持っている銘柄だけ） | 株数・取得単価・損益（率） |

- **高値・安値の期間**（v1.36.0〜）：表の上の［1年］［3年］［5年］［10年］で、**全銘柄いっしょに**替わります（29銘柄の点を見比べるため）。
  開くたびに1年から始まります（端末には覚えません）。選んだ期間の分の値動きがそろわない銘柄は「期間内」と書き、「○年分」と添えます。
  10年の安値は、29銘柄中11銘柄が 2020年3〜4月（コロナの暴落）、6銘柄が10年前の 2016年10〜11月です（2026-10-13 時点）。
  値上がりしてきた銘柄は、点が高く出やすくなります。安値・高値を付けた年月は、銘柄を押して開く詳細で見られます（v1.38.0〜。下を参照）。

- **いまの利回り** ＝ 過去1年の1株配当 ÷ いまの株価。割合だけだと配当の記録漏れや一時的な特別配当に気づけないので、**配当の額と並べて**出します。
  配当の記録が無い銘柄は「配当 記録なし」と出します（無配か取れなかったか見分けられないので、0% とは書きません）。
- **並べ方**：保有株の CSV で「持っている」「気になる」に分けます（公開側の順番は変えません）。それぞれの中は `feeds.json` の順です。
- **役割の札**（高配当・長期保有・優待）：銘柄を押して開いた詳細の中の札を押すたびに 高配当→長期保有→優待→高配当 と替わります
  （v1.37.0 までは行の札を押して替えていました。行を押すと詳細が開くようにしたので、押し間違えないよう詳細の中へ移しました。行の札は見せるだけです）。
  この端末だけに覚え（`mynews_roles`）、公開側には書きません。
  長期保有・優待の銘柄は利回りを控えめな色にし、合計の取得利回りは「高配当だけ」と「全体」を並べます。
  高配当の物差しで見ると低く見えたり、合計を押し下げたりするためです（例：昔から持っている SUBARU、優待目当てのパルグループ）。

#### 表の見方（凡例、v1.39.0〜）

ウォッチ銘柄の見出しの右の **［ⓘ 見方］** を押すと、期間の切り替えの下に、表の数字・棒・印・札の意味が開きます（もう一度押すと畳みます）。
左に実物と同じ見た目の見本、右に意味を並べます。毎朝じゃまにならないよう、開いた状態は端末に覚えず、開くたびに畳んだ状態から始まります。
中身は、押すと開く詳細（v1.40.0 から利回りの10年・1年ごとの配当も）・役割の札・▲▼・配当・いまの利回り・棒（選んだ期間の位置）・期間の切り替え（10年の安値は 2020年3〜4月のコロナの暴落の銘柄が多く、
値上がりしてきた銘柄は点が右に寄りやすい、という注意つき）。保有株を読み込んだ端末では、取得利回り・3行目・上の合計の説明も出ます。

#### 銘柄を押すと開く詳細（v1.38.0〜）

1〜3行目のどこを押しても、その下に詳細が開きます（名前の前の ▸ が ▾ に変わります。もう一度押すと閉じます）。
いくつでも同時に開けます。開いた状態は端末に覚えず、開くたびに全部閉じた状態から始まります。

| 中身 | 説明 |
|---|---|
| 期間ごとの表 | 1・3・5・10年の安値・高値と、それを付けた年月、いまの位置（安値0%〜高値100%）。表の上で選んでいる期間の行を太字にします。10年分が取れなかった銘柄は1年だけ |
| 過去1年の配当 | 1回ずつの権利落ち日と額、「合計 ÷ いまの株価 ＝ いまの利回り」の式。持っている銘柄は「合計 ÷ 取得単価 ＝ 取得利回り」も |
| 利回りの10年（v1.40.0〜） | 過去10年の利回りの最低・最高と年月、いまの利回りがその中のどこか（下から○%。下3分の1＝「低いほう＝配当に比べて株価が高め」、上3分の1＝「高いほう＝安め」）。棒にしないのは、株価の棒（右ほど割高）と向きが逆で取り違えやすいため。最高のときの配当が前後の年より3割以上多ければ「特別配当・記念配当かもしれない」と添える |
| 1年ごとの配当（v1.40.0〜） | 今の月で区切った1年ごとの合計11個。前の年の98%未満の年は青と ↓（「前の年より減った年」）、前後の年（どちらも配当あり）より3割以上多い年は ＊（特別配当・記念配当かもしれない）。過去1年が前の年より3割以上多ければ「特別配当なら、いまの利回りは高めに出ている」。年の区切りは決算の年とずれるので、中間と期末の配分が変わっただけでも増減して見えることがある（例：アンドエスティHD の2026年 100→90円は、決算の年ごとでは 90→90円）と断る |
| 役割 | 役割の札（押すと替わる。上を参照） |
| 外部の銘柄ページ | Yahoo!ファイナンス（株価・チャート：`finance.yahoo.co.jp/quote/コード.T`）と IR BANK（配当の推移：`irbank.net/コード/dividend`）。別のタブで開きます。2026-10-13 に29銘柄すべてで、その銘柄のページが開くことを確かめました |

ウォッチ銘柄に無い保有株は、株価の推移と配当を取っていないので、表と配当の代わりにそのことを書きます（役割と外部ページは出ます）。

- **取得利回り** ＝ 1株配当（過去1年の実績）÷ 取得単価。現在値は使いません。
  合計は「配当の合計 ÷ 取得額の合計」で、**配当が分かった銘柄だけ**で出します（何銘柄分かを添えます）。
- 株価は毎回の更新の値を使います。**ウォッチ銘柄に無い銘柄**（あとで買った株など）は、CSV に書かれた現在値で計算し
  「CSV ○/○ 時点」と出します。配当は出ません。毎朝の値がほしければ、ウォッチ銘柄に足してください。
- CSV で読むのは**株式の段だけ**です（投資信託・国債は読みません）。同じ銘柄が2つの段にあれば足し合わせます。
- CSV には日付が書かれていないので、**ファイルの保存日時**を「時点」として出します。
- 手で1銘柄ずつ直す欄はありません。変わったら CSV を読み込み直してください（置き換えです）。
- 「消す」で端末から消せます。CSV を読み込み直せば戻ります。

### ホイミ（v1.45.0〜）

新着をすべて確認すると、「✓ 新着はすべて確認しました」の下に「ホイミ」の枠が出ます。1〜2分でできるひと休みを3つ並べ、できそうなものを1つ選んでもらうものです。名前はドラゴンクエストの小さな回復の呪文から取りました。もとはストレスコーピングアプリ（slowdrift.github.io/Stress_Coping/）に任せていましたが、開くきっかけが無くて使われなかったので、毎日開くこのアプリに置いています。

3つは、体（動かす・ゆるめる）、息・五感・まわり、頭と心の3つの組から1つずつ選びます。サプリは手元に無ければ飲めず、体操は家でないとしにくいので、1つだけだとその場でできないことがあるためです。頭と心の組はほぼどこでもできるので、3つのうち少なくとも1つはその場でできます。最後にやってから日が空いた項目ほど選ばれやすく、同じ日のうちは開き直しても同じ3つが出ます。

できたものの［できた］を押すと記録して「HPが すこし かいふくした！」と出ます（5秒は元に戻せます）。［ほかの3つにする］を押すと、その日にまだ出していない項目で3つとも入れ替わります。この7日でできた日数は「⚙ 設定 → ホイミ」で見られ、同じ場所で出さないようにもできます。

項目は70個あります。コーピングアプリの1〜2分の項目が32個（音楽と自然音は曲や音ごとに分けています）、コーピングアプリの5〜15分の項目を1〜2分でできる形に縮めたものが15個（「首と肩を回す」「日記を1行だけ書く」など）、新しく足したものが23個（「背伸びをする」「遠くを見る」「楽しみな予定を1つ思い浮かべる」など）です。組ごとの数は、体17・息と五感30・頭と心23です。

記録はこの端末だけに置き（`mynews_hoimi`・`mynews_hoimi_log`）、記録の書き出しにも入ります。弱点は3つあります。縮めた15個と新しい23個の言い回し、組み分けは Claude が考えたもので、暮らしに合うかは使いながら確かめることになります。コーピングアプリとはつないでいないので、あちらの記録・★・自分で足した項目は使いません。項目を足したり外したりする画面は無いので、変えるときは `app.js` の `HOIMI_ITEMS` を書き換えます。

### 見終えるまでの時間（v1.45.0〜）

「短い時間で見終わる」ことを数字で見るため、その日の新着が残っていて画面が表に出ている時間を、日ごとに足していきます。新着が0件になった時点で「見終えた」とし、1日に何度か開いた日は合計にします。「⚙ 設定 → 見終えるまでの時間」に直近7日（例：10/29 4分12秒）と、見終えた日だけの平均が出ます。0件まで届かなかった日は「（途中まで）」と出て、平均には入れません。記録は直近60日分だけこの端末に残し（`mynews_donetime`）、書き出しにも入ります。

画面が裏に回っている間は数えません。放っておいた時間を混ぜないためですが、そのぶん記事を開いて読んでいる時間も入らないので、数字は「見出しを見て片づける時間」に近くなります。画面をつけたまま置いておいた時間は数えてしまいます（スマホは画面が消えると裏に回った扱いになるはずですが、実機では確かめていません）。また、［✓ 見終わったので全部片づけ］のあとで「元に戻す」を押しても、その日の「見終えた」の印は残ります。

### 朝刊の行の並べ替え（v1.37.0〜）

- 朝刊の「⚡ きょうの新着」の右端の **［↕ 並べ替え］** を押すと「並べ替え中」になり、行ごとに ▲▼ が出ます。
  記事ののぞき見・［✓ 片づけ］・発掘は、そのあいだ隠れます。
- 動かす単位は朝刊の1行です。まとめた行（人物・作品・地元・動画・海外ニュース）は、まとめて1行として動きます
  （まとめた行の中の順番は、これまでどおり「先頭に出す」テーマ＝大洗・アーミル・カーンが先）。
- 順番はこの端末に覚えます（`mynews_morning_order`。記録の書き出しにも入ります）。新着画面（見出しの数字から開く画面）も同じ順になります。
- 並べ替えたあとは、並べ替え中の一番下に **［元の順番に戻す］** が出ます（押したあと5秒は戻せます）。
- あとで増えたテーマは、元の並びで1つ前にある行のすぐ後ろに入ります。
- **元の並び**は、⚙設定の「書庫のテーマの並べ替え」の順（カテゴリの中だけ）で、動画は後ろ、ウォッチ銘柄のニュース（`"top": true`）が一番上です。
  書庫の並べ替えはカテゴリの中の順番なので、使っていると、元の朝刊ではそのカテゴリのテーマが上に寄ることがあります（v1.36.0 までと同じ）。
- v1.36.0 までは、ウォッチ銘柄のニュースを並べ替えに関係なく一番上に**固定**していました。
  利用者の意図ではなかったので、v1.37.0 から最初の位置を決めるだけにしました（下へも動かせます）。

### 指で払って仕分ける（スマホ）

| 動き | 効果 |
|---|---|
| カードを**右へ払う** | 既読にする |
| カードを**左へ払う** | ★お気に入りに入れる／外す |

払うとすぐ「**元に戻す**」が5秒出ます。指1本で消せてしまうので、必ず戻り道を用意しています。
**直近5件までさかのぼれます**（続けて払っても、新しい順に1件ずつ戻せます）。

操作の説明は「⚙ 設定 → 使い方」にあります。しばらく使わないと忘れるためです。

**気をつけた点3つ**

1. **端は避ける** — Androidは画面の左右どちらの端からのスワイプも「戻る」になるので、
   両端30pxから始まった指の動きは相手にしません。カードの中ほどから払ってください。
2. **縦スクロールと分ける** — 横の動きが縦よりはっきり大きくなってから初めてカードが動きます。
   斜めに動かしても誤爆しません（CSSの `touch-action: pan-y` で縦送りはブラウザに任せています）。
3. **距離が要る** — カード幅の1/4（最低60px）払わないと成立せず、途中で放すと元に戻ります。
| もっと見る | そのテーマの続きを30件ずつ出す |
| 読み返す | 読み終えたテーマの記事をもう一度出す（テーマは消えません） |
| 🎬 動画（あとで見る） | YouTubeは記事と分けて最下部に。既定は閉じています |

**画面の開き具合も覚えます。** カテゴリや動画ブロックを畳んだ状態、「もっと見る」で
広げた位置は、次に開いたときも同じです（毎朝畳み直す手間をなくすため）。
覚えるのは名前で行うので、テーマが増減しても位置がずれません。

既読の記録は**日数では消えません**（一度読んだ記事は読んだまま）。
記録が5000件を超えたときだけ、古いものから減らします。
また、同じ記事が別のURLで再登場しても既読のままになるよう、見出しからも鍵を作っています。
これらの記録は**この端末のブラウザにだけ**保存されます（端末をまたぐと共有されません）。
守るには、下の「記録の書き出し・読み込み」でファイルに控えておきます。

## 記録の書き出し・読み込み（v1.29.0〜）

既読・★お気に入り（記事の中身ごと）・👍👎・開閉状態などは、この端末のブラウザにしかありません。
ブラウザのデータ削除や機種変更で一度に失われ、お気に入りは蓄積から消えた記事も含むので二度と戻りません。
そこで「**⚙ 設定 → 記録の控え**」から、ファイルに書き出し・読み込めるようにしました。

| ボタン | すること |
|---|---|
| ⬇ 書き出す | 記録を `mynews-backup-日付-時刻.json` に保存（Android の Chrome では「ダウンロード」フォルダ） |
| ⬆ 読み込む | ファイルを選ぶと、**今の端末とファイルの件数を並べて見せる**だけ。「この内容に置き換える」を押すまで何も変わりません |
| ↩ 読み込む前に戻す | 読み込んだあと、**そのタブを閉じるまで**出ます。1回だけ戻せます |

- **書き出す範囲**：この端末に保存している「mynews_」で始まる記録すべて。名前で拾うので、
  記録の種類を増やしても書き足さずに対象に入ります。ページを開いている間だけの記録（スクロール位置）は入りません。
- **保有株だけは例外**：ボタンの横の「**保有株も入れる**」に印を付けたときだけ入ります（印は毎回外れた状態から）。
  書き出したファイルは分析のために Claude Chat へ渡すこともあるので、既定では金額の情報を入れません。
  分析用の写し（`analysis`）には、印を付けても入りません。
- **読み込みは「置き換え」**です（合算はしません）。書き出したあとにスマホで読んだ分は、読み込むと消えます。
  ただし**ファイルに保有株が入っていなければ、端末の保有株はそのまま残します**（確認の表に「今のまま残す」と出ます）。
- 壊れたファイルや別のファイルを選んでも、「マイニュースの記録ではありません」と出るだけで何も変えません。
  形の合わない記録だけを飛ばして、残りを読み込むこともあります（確認の表に件数が出ます）。
- ファイルの選択画面では種類で絞っていません。Android では `.json` で絞ると選べなくなることがあるためです。
- 書き出したファイルは**リポジトリに入れません**（`.gitignore` で除外済み）。個人の閲覧記録だからです。

### どう読んだかの記録（分析用）

v1.29.0 から、既読にするたびに**どの操作で・どの画面で**既読にしたかを記録します
（開いた／右へ払った／👎／テーマの✓片づけ／ここまで見た／発掘の片づけ／全部片づけ／選んで既読）。
「開いた記事」と「開かずに流した記事」を分けて、テーマごとの選び方を見直すためです。

- テーマと見出しも一緒に残すので、記事が蓄積から消えても何だったか分かります。
- 「元に戻す」を押すと、その記録も消します（流したと誤って数えないため）。
- 5000件を超えたら古いものから消します（既読の記録と同じ）。保存に失敗しても既読の動きは止めません。
- 設定の「すべて既読」は全件を1行ずつ残さず、「すべて既読にした」の1行だけ残します。
- **v1.29.0 より前の既読は、どの操作だったか分かりません**（書き出しには「不明」として入ります）。

### ファイルの中身

| 項目 | 中身 |
|---|---|
| `app` `format` `version` `exported_at` | 「マイニュースの記録」の印・ファイルの形の版・アプリの版・書き出した日時 |
| `analysis.read` | **1記事1行**。テーマ・見出し・発信元と、`acts`＝[いつ, どの操作で, どの画面で] を古い順に |
| `analysis.read_unknown` | 蓄積から消え、何の記事か引けなかった既読。リンクか見出しの先頭30字（記号抜き）だけ |
| `analysis.fav` | お気に入り（保存した日時・テーマ・見出し・発信元・リンク） |
| `analysis.sources` | 発信元ごとの 👍・👎・開いた回数（👎は v1.31.0 から数えていない） |
| `storage` | **復元用**。端末の記録そのもの。読み込みに使うのはここだけ。保有株（`mynews_holdings`）は選んだときだけ |

`analysis` は人や Claude が読むための写しで、読み込みでは使いません。
記録が上限まで貯まると、ファイルは約2.4MBになります（実測：既読5000・読み方の記録5000件のとき）。
