# マイニュース（個人専用ニュースアプリ）

スマホで毎朝開くだけで、関心ジャンルの見出しを一覧できる静的Webアプリです。
複数のフィード（RSS / Googleアラート / YouTube）を取得し、カテゴリ別に表示します。

- 継続コストゼロ（有料APIは不使用）
- 自動要約なし（見出し＋リンク中心に表示）
- 1つのフィードが落ちても全体は止まらない設計
- カテゴリは折りたたみ可能（初期は開いた状態）。YouTubeはサムネイル付きの動画カードで表示

## しくみ（収集と表示の分離）

| 役割 | ファイル | 種別 |
|---|---|---|
| 収集（Python） | `build_news.py` | フィード取得・整形・フィルタ → `data.js` を出力 |
| 設定 | `feeds.json` | フィード一覧（ここを編集して増減） |
| 表示（ブラウザ） | `index.html` + `app.js` | `data.js`（埋め込みデータ）を読み込んで描画 |

> 収集はビルド時（Python）に行います（ブラウザ直取得は CORS で不可のため）。
> データは `window.NEWS_DATA` として `data.js` に埋め込むので、
> **ローカルサーバ無し・ファイルを直接開くだけ**で表示できます。

## 使い方（ローカル）

1. ライブラリを入れる（初回のみ）
   ```
   pip install -r requirements.txt
   ```
2. データを更新する
   ```
   python build_news.py        # → data.js を作成/更新
   ```
3. **`index.html` をダブルクリックで開くだけ**（ブラウザで表示されます）。
   毎朝は 2→3 を繰り返すか、`build_news.py` を実行後に開いてある画面を再読み込みします。

実行すると各フィードの取得結果が画面に出ます。詳しい記録は `fetch.log` に残ります。

## フィードの増やし方

`feeds.json` を編集します（コードは触りません）。カテゴリごとにフィードを足すだけです。

```json
{
  "categories": [
    { "name": "仕事・AI", "feeds": [
      { "name": "ITmedia AI＋", "url": "https://rss.itmedia.co.jp/rss/2.0/aiplus.xml" }
    ]},
    { "name": "料理", "feeds": [
      { "name": "リュウジのバズレシピ",
        "url": "https://www.youtube.com/feeds/videos.xml?channel_id=UCW01sMEVYQdhcvkrhbxdBpw",
        "type": "video" }
    ]}
  ]
}
```

- 動画フィード（YouTube）は `"type": "video"` を付けるとサムネイル付きで表示。
  YouTubeのURLは `https://www.youtube.com/feeds/videos.xml?channel_id=（チャンネルID）`。
- **秘密のURL（Googleアラート等）は値を書かず** `"url_env": "環境変数名"` で参照します。
  実際の値はローカルは `.env`、GitHub Actions は Secrets に登録（公開ファイルに出さないため）。
- アラート系は `"alert": true` を付けると多層フィルタ（発信元サイト除外・NGワード・必須語）を適用。
  `"require": ["語"]` でタイトルに含むべき語、`"exclude": ["語"]` で個別NG語を指定できます。

## 読めない記事の扱い

本文が読めない記事でがっかりしないよう、2段構えで判定しています。

1. **実ページで確認（確実）**：直リンクの記事は実際にページを見て、
   「有料会員限定」等の文言と、サイトが宣言する `isAccessibleForFree`（無料かどうか）で判定します。
   文言のほうを優先します（無料と申告しつつ本文を隠す媒体があるため）。
2. **媒体リストで推測（補助）**：Googleニュース経由の記事は実URLに辿り着けないため、
   `paywall.json` の配信元名・**発信元ドメイン**で推測します。1で分かった事実があれば、そちらを優先します。

判定結果による表示の違い（読めないものはすべてテーマ内の**末尾**へ回します）：

| 判定 | 意味 | 表示 |
|---|---|---|
| 🔒 有料 | お金を払わないと読めない | 🔒バッジ・見出しを控えめな色に |
| 会員限定 | 登録・ログインすれば無料で読める | 青い「会員限定」バッジ |
| 一部有料 | 無料記事も多いが会員限定も混じる媒体 | 控えめな「一部有料」バッジ |
| 無料 | そのまま読める | バッジなし |

**NHKは受信料契約が要るため、番組も記事も有料扱い**にしています。

媒体リストは `paywall.json` を編集すれば調整できます。
**社名は略称と正式名の両方を書き、ドメインも併記してください。**
部分一致のため、「日経」だけでは「日本経済新聞」に一致しません（実際に取りこぼしていました）。

実ページ確認を止めたい場合は `build_news.py` の `VERIFY_PAYWALL = False` にします
（確認は並行処理で、全体で20〜30秒ほど増えます）。

## 記事を貯める（消えない仕組み）

一度見つけた記事は `archive.json` に貯め、消しません（テーマごと既定500件）。
毎回ゼロから取り直すと、読もうと思っていた記事が翌日には消えてしまうためです。

**貯めた記事は全部 `data.js` に載せます。** 収集側は選びません。
以前は1テーマ30件だけを渡していたため、貯めた記事の73%が画面に届かず、
読み切ると「すべて読み終えました」と出ていました（実際には未読が残っていた）。
**どれを出すかは、既読を知っている表示側が決めます。**

- 画面はテーマごとに30件ずつ描き、下の「**さらに古い記事**」で伸ばします。
- 読んで消えた分は、次の記事が繰り上がります。読むほど古い記事へ降りていけます。
- 取得に失敗したテーマも、蓄積があればそのまま表示します
  （配信側が落ちた日にテーマごと消えるのを防ぐため）。

蓄積の上限はテーマごとに変えられます。上限を超えると**配信日の古い順に捨てます**。
既読かどうかは収集側から分からないため、**未読でも古ければ捨てられます**。
流量の多い技術系テーマだけが上限に達し、人物テーマは到達しないことがほとんどです。

```json
{ "topic": "沢木耕太郎", "keep": 1000 }
```

★お気に入りにした記事は端末に中身ごと保存されるので、蓄積から消えても読めます。

- **`first_seen`**：その記事がアプリに初めて入ってきた日時。NEW判定はこれを使います
  （記事の配信日で判定すると、過去の記事しか無い日は永久にNEWが付きません）。
  **NEW＝「まだ読んでいない、7日以内にアプリへ入ってきた記事」**です。
  何度開いても7日間は光り、読めば消えます。
  ただし**初めて開いた日より前に集まっていた記事には付けません**
  （付けると初回や情報源を増やした日に全件が光り、意味をなさないため）。

**見出しに出る数字は「きょうの新着」（24時間以内に届いた未読）です。**
NEWの印は7日光らせていますが、その数を出すと7日分＝1700件になり、
「今日なにを読めばいいか」の指標として働きません（実測で全件が該当しました）。

| | 意味 | 期間 |
|---|---|---|
| 見出しの数字 | **きょうやること** | 24時間 |
| カードのNEW印 | 数日空けても**見逃さない**ための印 | 7日 |

カテゴリの数字も同じで、大きい数（未読の合計）は小さく添えるだけにしています。

**この数字を押すと「きょうの新着」だけの画面**になります。新着があっても、
どのテーマにあるかスクロールして探すしかなかったためです。
テーマの並びは `feeds.json` の順のまま動かしません（毎日同じ場所にある安心感を保つため）。
別の入口として用意しています。「← 全部を見る」で戻ります。
テーマごとに「✓ 既読に」があり、**今日は見ないテーマを一括で片づけられます**。

**NEWバッジと「1か月以上前の記事」の区切りは、役割が違います。**

| | 意味 | 基準 |
|---|---|---|
| NEW（黄バッジ） | まだ読んでいない**新着** | アプリに入ってきた日 |
| 区切り線 | 記事そのものの**古さ** | 記事の配信日 |
- **情報源を広げる**：蓄積が40件に届かないテーマには、ニュース以外にも当たります。
  Googleニュース検索は `site:` 指定に対応しており、報道以外のページも索引にあるためです。
  既定で `note.com` `hatenablog.com` `1101.com`（ほぼ日）を試します。
- **過去へ遡る補充**：それでも足りなければ、
  `after:2018-01-01 before:2022-01-01` のように**期間を区切って**聞き直し、
  最大20年前まで遡ります。検索は既定だと最近の記事しか返さないためです。

## 情報源を名指しで足す

「ニュースには出ないが、あのサイトには書かれている」を拾うための仕組みです。

```json
{ "topic": "近藤紘一", "sites": ["1101.com", "note.com", "bunshun.jp"] }
```

- 実測：ニュース検索だけでは5件だった近藤紘一が、
  note.com で54件、文藝春秋で20件、はてなブログで10件見つかりました。
- **`sites` のときだけ、見出しに検索語が無くても採用します。**
  求めてしまうと「本文で語っているブログ記事」がすべて落ちるためです。

### 「関連」の印

サイト指定で集めると、**本文で名前に触れているだけ**の記事が混じります
（実測：近藤紘一は66件中51件が見出しに名前なし）。
見出しにテーマの語が無い記事には「**関連**」の印を付け、**テーマ内の末尾へ回します。**
消さないのは、周辺の読み物にも当たりがあるためです。

### 検索語の足し方（同じテーマに複数の切り口）

`group` を同じにすると、別の検索語を1つのテーマに合流できます。

```json
{ "topic": "\"きっとうまくいく\" アーミル", "group": "アーミル・カーン",
  "require": ["きっと、うまくいく", "アーミル"] }
```

**必須語（require）は絞り込みであって、検索の範囲は広げません。**
作品名の記事を拾いたいなら、作品名で検索する行を足す必要があります
（実測：これで「17年ぶり続編へ」等15件が入りました）。

英語のソースには `require_en` を使います。日本語の語を当てると英語の見出しは全滅します。

### そのほかの絞り込み

| 書き方 | 効果 |
|---|---|
| `"min_views": 10000` | 動画の再生回数がこれ未満なら取り込まない |
| `"views_exempt": ["安野貴博"]` | ただし見出しにこの語があれば回数によらず残す |
| `"no_ng": true` | 全体のNGワードを外す（テーマ自体が「Amazon」「セール」等と重なる場合） |
| `"daily_max": 20` | 1日に「新着」として名乗れる数（既定20件） |
| `"minor": true` | **ときどき見れば良いテーマ**（下記） |

### ときどき見るテーマ

`"minor": true` を書くと、そのテーマは次の扱いになります。

- **「きょうの新着」に数えない**（毎朝の数字を実態に合わせるため）
- カテゴリの**下部**に「ときどき見る」の区切りを挟んでまとめる
- **既定で畳む**（見出しと件数だけ見える。開閉は覚えます）
- **NEWの印は付く**（開いたとき、新しいものが分かる）

**別カテゴリに移す方法は採りませんでした。** 頻度は分類ではなく扱いの強弱なので、
カテゴリを分けると「あの人はどこ？」と探すことになります。同じ場所に控えめに置きます。

実測：アーミル・カーンは1日26件で人物テーマの中で最多でした（沢木耕太郎14件の倍近く）。

**`daily_max` は捨てるための設定ではありません。** 超えた分も蓄積に入り、
掘れば読めます。新着として数えないだけです。
実測で1日142〜175件が入りますが、その6〜7割をClaude Codeと生成AIが占め、
沢木耕太郎の1件がその中に埋もれていました（149件→92件、仕事・AIの占有率 66%→43%）。

### ブログの種類

| 印 | 中身 |
|---|---|
| 個人ブログ | note・はてなブログ・個人のZenn/Qiita |
| 企業ブログ | ○○ Tech Blog・株式会社○○・公式アカウント |

並び順は変えません（技術テーマでは企業のテックブログも役立つため）。

## 読みたい記事を前に出す

テーマの行に `prefer`（優先）と `demote`（後回し）を書けます。**記事は消えません。**

```json
{ "topic": "井上陽水",
  "prefer": ["出演", "インタビュー", "新曲"],
  "demote": ["BGM", "挿入歌", "カバー"] }
```

`demote` は `prefer` より強く効きます。
「コンサート」のような語は本人の出演でも他人の演奏会でも当たるため、
優先を強くすると『アマチュア音楽家が名曲を披露』のような記事が先頭に来てしまうからです。
完全に消したいものは `exclude` を使います（こちらは表示されなくなります）。

## 天気と株価

`feeds.json` の先頭に設定します。どちらも**取れなければ黙って消えます**（ニュースの取得は止めません）。

```json
"weather": { "area": "080000", "point": "水戸" },
"stocks": [ { "code": "2726.T", "name": "パルグループHD" } ]
```

- **天気**：気象庁の公開データ。APIキーも登録も要りません。`area` は地域コード（080000＝茨城県）。
  今日と明日を、アイコン・気温・**通勤（朝6-12時）と退勤（夕12-18時）の降水確率**で出します。
  **時間帯別の天気（晴/曇/雨）は気象庁が公開していません。** 出せるのは1日単位の天気と、
  6時間ごとの降水確率だけです。アイコンは1日単位のものです。
- **株価**：記事とは別のブロック（最下部）に銘柄を並べます。
  あわせて**天気の下に現在値だけ一行**添えます（押すと最下部へ飛びます）。
  最下部だけだと朝のひと目に間に合わないためです。`code` は東証なら「数字.T」、
  日経平均は `^N225`、ドル円は `JPY=X`。上げは赤、下げは青（日本の慣習）。
  **取得先は公式に開放されたものではありません。** 使えなくなったら表示が消えるだけです。

## 画面の使い方

| 操作 | できること |
|---|---|
| 記事を開く | 自動で既読になり、次に開いたときは一覧から消えます |
| ★（記事の右上） | お気に入りに保存。**一覧から消えても、既読にしても残ります** |
| ★ お気に入り | 保存した記事だけの画面に切り替え |
| ☐ 既読も表示 | 読んだ記事も含めて表示 |
| ✓ 既読に | そのテーマをまとめて既読に |
| ✓ まとめて既読 | カードを押して選び、下のバーで**まとめて既読に** |
| 🔒（テーマの見出し） | そのテーマの読めない記事だけ既読に |
| ⚙ 設定 | 配色・文字サイズ・すべて既読（毎日は使わないものを畳んである） |

### 画面の広さ

広い画面（1000px以上）では**2列**になります。1440pxで中身720px・左右360pxずつ
空いており、縦が7画面分ありました（→ 5.8画面分）。
スマホは1列のままです（横に並べると1件あたりが窮屈になるため）。

### 指で払って仕分ける（スマホ）

| 動き | 効果 |
|---|---|
| カードを**右へ払う** | 既読にする |
| カードを**左へ払う** | ★お気に入りに入れる／外す |

払うとすぐ「**元に戻す**」が5秒出ます。指1本で消せてしまうので、必ず戻り道を用意しています。
**直近5件までさかのぼれます**（続けて払っても、新しい順に1件ずつ戻せます）。

操作の説明は「⚙ 設定 → 使い方」にあります。しばらく使わないと忘れるためです。

**気をつけた点3つ**

1. **端は避ける** — Androidは画面の左右どちらの端からのスワイプも「戻る」になるので、
   両端30pxから始まった指の動きは相手にしません。カードの中ほどから払ってください。
2. **縦スクロールと分ける** — 横の動きが縦よりはっきり大きくなってから初めてカードが動きます。
   斜めに動かしても誤爆しません（CSSの `touch-action: pan-y` で縦送りはブラウザに任せています）。
3. **距離が要る** — カード幅の1/4（最低60px）払わないと成立せず、途中で放すと元に戻ります。
| もっと見る | そのテーマの続きを30件ずつ出す |
| 読み返す | 読み終えたテーマの記事をもう一度出す（テーマは消えません） |
| 🎬 動画（あとで見る） | YouTubeは記事と分けて最下部に。既定は閉じています |

**画面の開き具合も覚えます。** カテゴリや動画ブロックを畳んだ状態、「もっと見る」で
広げた位置は、次に開いたときも同じです（毎朝畳み直す手間をなくすため）。
覚えるのは名前で行うので、テーマが増減しても位置がずれません。

既読の記録は**日数では消えません**（一度読んだ記事は読んだまま）。
記録が5000件を超えたときだけ、古いものから減らします。
また、同じ記事が別のURLで再登場しても既読のままになるよう、見出しからも鍵を作っています。
これらの記録は**この端末のブラウザにだけ**保存されます（端末をまたぐと共有されません）。

## メモ

- 取得できなかったフィードは自動でスキップされ、`fetch.log` に記録されます。
  **画面の見出し横にも「⚠ N件届かず」と出ます**（押すと内訳）。
  貯めてある記事が表示されるので画面は普段どおりに見えてしまい、
  ログだけでは壊れていることに気づけないためです。
  ただし「0件（フィルタ後）」は絞り込みが効いた正常な結果なので数えません。
  何でも警告にすると、本当に困ったときに信用されなくなります。
- **更新が半日以上あいたら**、見出しの「◯時間前」が警告色になります
  （朝と昼の2回更新しているため）。
- 日時は日本時間で表示し、カテゴリ内は新しい順に並びます。

## 更新のタイミング

**朝と昼の2回、自動で更新します**（手作業は不要）。

| | 予約 | 実際に届く目安 |
|---|---|---|
| 朝 | 04:30 JST | **06:00〜06:40** |
| 昼 | 10:30 JST | **12:00〜12:40** |

控えをもう1本ずつ置いています（朝06:10・昼12:10の予約）。

**時刻は保証されません。** GitHubの予約実行は混雑時に待たされ、実測では
90〜126分遅れていました（毎時0分がいちばん混みます）。そこで**届けたい時刻より
約1時間半早く予約**しています。前倒しは確率を上げるだけで、混雑次第では
遅れる朝もあります。

なお、**60日間リポジトリに動きがないとGitHubが予約実行を止めます**
（事前にメールが届きます）。
